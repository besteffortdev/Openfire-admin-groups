Admin Console Groups

Lets the members of chosen user groups sign in to the Openfire admin console. For example, an Active Directory group such as Domain Admins. The accounts already marked Is Administrator keep their access; the groups only add to them.

Using it

Open Server > Server Manager > Admin Console Groups and add a group. Its members can sign in at once. The page also lists every account that can use the console, and why: the admin list or a group.

  • A group's own administrators count as members.
  • Only accounts on this server are made administrators. A member from another server is ignored, so a remote account can never gain administrator rights through a group.
  • Someone removed from the group loses access at the next refresh. Their open admin console session ends at their next page load, because Openfire checks on every request.
  • You cannot remove the group that is your only source of access. Remove it while signed in as another administrator.
  • Renaming a group in Openfire updates the setting. Deleting a group removes it, so a new group created later with the same name does not get administrator rights.

How fast changes count

Openfire keeps a cached list of administrators. The plugin rebuilds that list

  • right after any change to a configured group made in Openfire,
  • whenever the setting changes, and
  • every plugin.admingroups.refreshSeconds seconds (default 60).

The timer is how a change made directly in LDAP or Active Directory is picked up: those raise no event in Openfire. Each refresh reads the groups past Openfire's group cache.

Declaring the groups in openfire.xml

The groups can also be declared in Openfire's own conf/openfire.xml. The block is read when the plugin starts, and again when Read the configuration file is pressed on the admin page. The file is never written. 

<jive>
  <admingroups refreshSeconds="60">
    <groups>
      <group name="Domain Admins"/>
    </groups>
  </admingroups>
</jive>
  • A <groups> element replaces the whole group list, so removing a group from the file revokes it at the next read. An empty <groups/> clears the list; leaving <groups> out leaves the list alone.
  • A group that is not found is kept, with a warning, in case LDAP is unreachable at start-up. It makes nobody an administrator until it can be read.
  • The button refuses to apply a list that would lock out the administrator pressing it.

Settings

System propertyDefaultMeaning
plugin.admingroups.groups empty Comma-separated names of the groups whose members are administrators. The admin page edits it.
plugin.admingroups.refreshSeconds 60 Seconds between re-reads of the groups, from 10 to 86400.
plugin.admingroups.previousProvider empty Written by the plugin: provider.admin.className as it was before the plugin replaced it. Do not edit.

How it works

While loaded, the plugin sets provider.admin.className to its own provider. That provider wraps the one configured before, so the stored admin list, or a JDBC provider, keeps working. Unloading the plugin puts the previous value back.

If provider.admin.className is changed by hand while the plugin is loaded, the plugin steps aside, and its page says so. Reload the plugin to wrap the new provider.

Members also count as administrators everywhere else Openfire asks the same question. For example, the XEP-0133 service administration commands.

Requirements

  • Openfire 5.0.5 or later.
  • Not tested in a cluster.
